### Dimension 2 — Code Quality & Correctness

5. **HIGH** — Dry-run footgun in [trader/mod.rs:47](file:///home/kt/tabs/resilient-token-protocol/rtp/swarm/src/trader/mod.rs#L47): `let dry_run = std::env::var("RTP_TRADER_DRY_RUN").is_ok();` treats *any* value (including `"false"`, `"0"`) as dry-run = true. Operators expecting `RTP_TRADER_DRY_RUN=false` to enable live trading will instead get permanent dry-run. **Fix:** parse the value (`.map(|v| v != "0" && v.to_lowercase() != "false")`).

6. **MEDIUM** — Profit-factor leak in [night_shift.py:349](file:///home/kt/tabs/resilient-token-protocol/research/orchestration/night_shift.py#L349) `net_losses = [p for p in trade_pnls if p <= 0]`. Zero-PnL trades are counted as losses, dragging `avg_loss` toward zero and inflating `oos_pf`. Same pattern at [night_shift.py:1657-1660](file:///home/kt/tabs/resilient-token-protocol/research/orchestration/night_shift.py#L1657). Use `< 0`.

7. **MEDIUM** — Inconsistent overflow handling on the same field: [lib.rs:578-580](file:///home/kt/tabs/resilient-token-protocol/rtp/programs/rtp-treasury/programs/rtp-treasury/src/lib.rs#L578) uses `saturating_add` on `total_fees_received_lamports`, while [lib.rs:795-799](file:///home/kt/tabs/resilient-token-protocol/rtp/programs/rtp-treasury/programs/rtp-treasury/src/lib.rs#L795) uses `checked_add` on the same field. Pick one — saturating silently corrupts pro-rata yield math, checked aborts but is recoverable.

8. **MEDIUM** — Misleading constants in [lib.rs:24-25](file:///home/kt/tabs/resilient-token-protocol/rtp/programs/rtp-treasury/programs/rtp-treasury/src/lib.rs#L24-L25): comments say "$50k" / "$1M" but `SUSTENANCE_CAP = 50_000_000_000` is **lamports** (= 50 SOL), and `evolve_phase` compares against `available_treasury_lamports`. Same issue at [lib.rs:32](file:///home/kt/tabs/resilient-token-protocol/rtp/programs/rtp-treasury/programs/rtp-treasury/src/lib.rs#L32) — `DEFAULT_MIN_RUNWAY = 10_000_000` is 0.01 SOL, comment says "10 tokens". CLAUDE.md acknowledges the no-oracle limitation, but the comments themselves are wrong. **Fix:** rename to `*_LAMPORTS` and correct comments.

9. **LOW** — Wrong error code on `freeze_treasury`/`unfreeze_treasury` Anchor constraint at [lib.rs:1686, 1699](file:///home/kt/tabs/resilient-token-protocol/rtp/programs/rtp-treasury/programs/rtp-treasury/src/lib.rs#L1686): both fire `UnauthorizedPhaseEvolution` when the wrong signer attempts a freeze. Misleading audit logs. Add a freeze-specific error variant.

10. **LOW** — Redundant authority check in `update_strategy_performance`: explicit `require!` at [lib.rs:888-891](file:///home/kt/tabs/resilient-token-protocol/rtp/programs/rtp-treasury/programs/rtp-treasury/src/lib.rs#L888) plus Anchor constraint at [lib.rs:1631](file:///home/kt/tabs/resilient-token-protocol/rtp/programs/rtp-treasury/programs/rtp-treasury/src/lib.rs#L1631). Pick one (prefer the constraint, per v1.2 remediation pattern).

11. **LOW** — `evaluate_leverage_candidate` liquidation path at [night_shift.py:1599-1604](file:///home/kt/tabs/resilient-token-protocol/research/orchestration/night_shift.py#L1599) recomputes `position = capital * position_pct` at *liquidation time*, not at *entry time* — overstates margin loss for trades that opened when capital was lower. Track entry-time margin per trade or document the simplification.

### Dimension 3 — Security

12. **HIGH** — Slippage-direction asymmetry between open and close. [lib.rs:1129-1133](file:///home/kt/tabs/resilient-token-protocol/rtp/programs/rtp-treasury/programs/rtp-treasury/src/lib.rs#L1129) (open) computes `slippage_mult = 10000 + slippage_bps`, then for Long uses `price * slippage_mult / 10000` (= price ↑) — correct for buying. For Short it uses `price * (20000 - slippage_mult) / 10000` (= price ↓) — also correct. Close ([lib.rs:1316-1320](file:///home/kt/tabs/resilient-token-protocol/rtp/programs/rtp-treasury/programs/rtp-treasury/src/lib.rs#L1316)) inverts: Long = price ↓, Short = price ↑. Both directions appear correct, but they were derived independently — please add a unit test asserting the exact slippage_price values for representative inputs to prevent regression. Currently zero on-chain tests cover slippage math.

13. **MEDIUM** — `ChainConfig.test_default()` is `pub` (not `cfg(test)`) at [chain_client.rs:205](file:///home/kt/tabs/resilient-token-protocol/rtp/swarm/src/chain_client.rs#L205). It will be linked into release binaries. Gate behind `#[cfg(test)]` or `#[cfg(feature = "test-utils")]`.

14. **LOW** — Invariant #16 from CLAUDE.md ("PDA seed validation on `RecordFeeDeposit.treasury` and `RegisterAdopter.treasury`") is enforced via `seeds = [TREASURY_SEED, treasury.authority.as_ref()]`, but `treasury.authority` is read from the `Treasury` account itself — circular. Combined with the Anchor `bump = treasury.bump` check this is fine in practice, but consider documenting why the constraint is sufficient.

15. **LOW** — `emergency_close_all_positions` at [lib.rs:1392](file:///home/kt/tabs/resilient-token-protocol/rtp/programs/rtp-treasury/programs/rtp-treasury/src/lib.rs#L1392) operates on a *single* `strategy_record`, but only zeros that strategy's counters and decrements the treasury's global counter by that strategy's amount. If multiple strategies have open positions, calling it once doesn't reset the others. The doc says "max 3 positions" but doesn't note "per strategy". Either rename or add a loop over strategies.

### Dimension 4 — Test Coverage

16. **MEDIUM** — No test exists for the slippage_bps boundary (0 / 10000 / 10001) on `open_flash_position` or `close_flash_position`. Failing the bound returns `PositionSizeExceeded` ([lib.rs:1080,1284](file:///home/kt/tabs/resilient-token-protocol/rtp/programs/rtp-treasury/programs/rtp-treasury/src/lib.rs#L1080)) — semantically wrong error reused. Add tests asserting both behavior and a dedicated `InvalidSlippage` error.

17. **MEDIUM** — `emergency_close_all_positions` has no anchor test asserting that `previous_committed_sol_lamports > treasury.committed_sol_lamports` is handled gracefully (the code uses `saturating_sub` on treasury). Add a test where strategy committed > treasury committed (data-corruption case) to prove no panic.

18. **MEDIUM** — `test_decay_monitor.py` covers hard stops, soft decay, serialisation, and window pruning — but does **not** test (a) the `MIN_RECOVERY_TRADES = 3` recovery counter logic added in v1.2, or (b) interaction with `update_strategy_performance` on-chain. The Rust on-chain side is also missing an explicit recovery-counter test sequence.

19. **LOW** — `evaluate_on_fold` and `evaluate_leverage_candidate` have no Python unit tests for the compounding path (e.g., a single fold with one liquidation + one win, asserting expected ending capital). All current verification is integration-style via full night-shift runs.

20. **LOW** — `chain_client::tests` only asserts account counts and discriminator prefix; no test verifies the byte layout of the instruction `data` matches what the on-chain program parses (no shared fixture between client builder and program decoder). One round-trip test would catch divergence at compile time.
